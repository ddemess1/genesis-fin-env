# DESIGN — записка о дизайне

## Устройство

```
seed + config → чистая книга (A) → мутаторы → dirty + MutationRecord[] → truth/provenance → самопроверка (B, I01–I17)
             → public/ (6 файлов) | sealed/ (truth, provenance, selfcheck) → среда (читает только public) ↔ оценщик (читает sealed)
```

* Деньги — `int` в минимальных единицах, курсы — `Decimal` из строки, округление ROUND_HALF_EVEN; время — ISO-8601 с фиксированным смещением;
  `DetRng` с дочерними потоками на стадию и на мутацию (`random.Random` от blake2b, без float).
* Эталон выводится только из `MutationRecord` (`mutations/truth.py`; тест `test_hygiene` следит, кто пишет `truth.json`).
* Эпизод записывается, только если прошли все 17 инвариантов; иначе `EpisodeInvalid(seed, инварианты, mutation_id)` и ни одного файла на диске.
* Среда не хранит seed, MutationRecord и id_map. Оценщик — отдельный процесс (JSON по stdin/stdout); в закрытом режиме награды 0, `info={"steps_left"}`.
* Публичные ID — `PREFIX-` + 6 символов base32 от blake2b с солью; порядок таблиц перемешан; ID клона не соседствует с оригиналом.

## Мутаторы и двойники (6 ошибок, 7 двойников, 2 взаимодействия)

| Тип | Ошибка | Двойник с единственным отличающим признаком |
| --- | --- | --- |
| `duplicate_invoice` | клон счёта + проводки | TWIN_SUBSCRIPTION — `service_period` следующего месяца |
| `payment_allocation` | MISSING / PARTIAL (часть уходит в 2900) | TWIN_SPLIT_PAYMENT (два платежа, 2900=0), TWIN_TRUE_PARTIAL (ref < total), TWIN_REFUND (`amount_minor<0`), TWIN_OVERPAYMENT (платёж > ref: ref целиком в 1200, излишек — аванс в 2900) |
| `fx_conversion` | WRONG_FX_DATE / WRONG_FX_RATE (разница через 7900) | TWIN_WEEKEND_FX (нет курса на выходной, правило «последний ≤ даты») |
| `period_cutoff` | счёт следующего периода проведён задним числом | TWIN_BOUNDARY_TZ (`2026-11-01T01:30+09:00` = 31.10 по поясу manifest) |
| INT1 | PARTIAL/MISSING + WRONG_FX_DATE на одном валютном платеже в последние сутки периода | |
| INT2 | дубль с клоном в следующем периоде + PERIOD_CUTOFF на клоне | |

У каждого двойника в `params.distinguishing_feature` — строка-признак (визуал без неё отказывается строить граф).

## Решения при неоднозначностях (кроме уже решённых в разделе 7 тех-ТЗ)

1. Проводок 200–2000 при документах 20–200 недостижимо без «прочих» проводок (аренда, комиссии, повторяющиеся суммы) — они без документов и служат шумом.
2. Платёж ссылается на один счёт (схема допускает список).
3. Сумма `payment_allocation` = `max(0, ref − round(ΣCr1200·A/(ΣCr1200+ΣCr2900)))` по платежу (A — сумма платежа; излишек A над ref законен): совпадает с «ref − распределённое», не зависит от курса
   и поэтому проверяема при τ=0, в том числе когда та же запись испорчена FX-ошибкой.
   Для валют ценой < 1 минимальной единицы базовой часть платежа по леджеру не восстанавливается — мутатор подбирает долю, при которой round-trip точный, иначе пропускает цель.
4. Документы следующего периода (окно +3 дня в policy) существуют без проводок; `PERIOD_CUTOFF` добавляет проводки.
5. Периоды — календарные месяцы 30–31 день (подписочная пара «+28…31 день» должна остаться в периоде).
6. У дубля одна допустимая пара доказательств `{doc(I), doc(I')}`: альтернатива из примера тех-ТЗ `{doc(I), row_AR(I')}` не позволяет независимо пересчитать сумму в валюте счёта (I09).
7. Отличия от тех-ТЗ: инварианты и аудит проверяют I09 «достаточность» на урезанной книге; C-проверки изолированы try/except, а не процессами; масштаб SVG-графа — динамическая ширина столбцов (фиксированные 190 px не вмещают наборы доказательств); цвет текста на матрице — лучший по контрасту из белого/#222 (правило «белый при |r|≥0.5» не даёт 4.5:1 на стандартной RdBu).
8. Если документ противоречит кейсу — выигрывает кейс; противоречий по существу не найдено (поля, лимиты, награда взяты из PDF №1).
9. Единственный float в системе — награда на границе API (`to_json_number`); деньги никогда.

## Честные ограничения

* Самоаудит (90/90) — **наша трактовка** критериев; у жюри может быть иначе. Критерии на сайте могли обновиться — перечитать перед сдачей.
* Данные синтетические и «чистые»: книга всегда сходится по двойной записи; реальные аудиторские ошибки (подлог, сговор, ошибки классификации) не моделируются.
* Простая сверка и случайная политика — слабые базовые линии; награда в матрице — диагностика среды, не доказательство качества агента. Улучшения модели не заявляем.
* Независимость детекторов обеспечена границей модулей (тест на импорты) и тем, что автор один; полноценная «вторая пара глаз» не заменена.
* Python 3.13 использовался локально; образ Python 3.11 (Dockerfile) собран в документации, но **не запускался** на этой машине (нет Docker).
* Скорость: ≈ 0.12 с/эпизод на Windows с антивирусом (1000 seed = 116 с), цель «<60 с на 1000» из тех-ТЗ выполнится только на быстрой ФС; основная стоимость — запись файлов.
* Проверка `C18` реально ждёт 61 с (в `--fast` — 2 с).
* Утечка seed проверяется подстрокой только для seed ≥ 8 знаков (короткие числа совпадают с суммами) плюс слово `seed` и 12-значный зонд в C20.

## Сложность базовых политик

Добавление TWIN_OVERPAYMENT снизило среднюю награду «простой сверки» с +0.33 до +0.21 (оплаты +0.98 → +0.54, FX +0.98 → +0.78): наивная проверка «2900 > 0» ловится на законном авансе.

## Измеренные сбои (и что с ними сделано)

1. **1000 seed, первый прогон:** 43 `GenerationError: no eligible target for INT1`, 3× `I16`, 2× `I17`; после исправлений второй прогон дал ещё 4× `I16` (id эпизода `ep_d6081234` совпал с шаблоном внутреннего ID), третий — 0 сбоев. Причины и исправления:
   * INT1: PARTIAL_ALLOCATION на валютах с курсом < 1 минимальной единицы базовой (JPY/KWD → USD/EUR) давал неточный возврат суммы из леджера
     (`round(A·ΣCr2900/…) ≠ A−alloc`), мутатор пропускал все цели. Исправлено подбором доли + выбор валют в сэмплере.
   * I16: ложное срабатывание — seed 100000 совпал с круглой суммой; короткий seed `1` совпадал с `"1.0"`; случайный ID `ROW-INT2XX` содержал `INT2`; hex-id эпизода из букв+цифр совпал с шаблоном внутреннего ID. Исправлено (длина токена, границы).
   * I17: конфиг давал 191 проводку при минимуме 200 — генератор теперь дополняет «прочие» проводки до 220.
2. **Разработка:** переименование каталога эпизода падало с `PermissionError` в папке, которую синхронизирует OneDrive — добавлен откат на `copytree`;
   кэш аудита вынесен в системный temp.
3. **`--inject-bug`:** `dup` роняет M05 (награда за дубль вывода) и утверждение матрицы; `order` — все P01–P20; `leak` — C20 (blocking) и защиту траекторий. Реальный отчёт не перезаписывается.

Итог: 1000 эпизодов, 0 сбоев, 116 с (`reports/stress.json`).
